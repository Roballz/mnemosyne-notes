# Mnemosyne记事簿

TauriTavern 独立前端扩展。楼层收藏、手机消息和备忘录均从当前聊天原文回看，聊天切换与分支各有自己的记事簿。

## 安装与共存

在 TauriTavern 的「扩展 → 安装扩展」中粘贴下面的 Git URL，分支栏留空。

```text
https://github.com/Roballz/mnemosyne-notes.git
```

安装完成后重载前端。记事簿和日用记忆分别安装到独立目录，可以同时使用。今后可在扩展管理中为记事簿单独点「更新」。本插件也已启用 `auto_update`，自动更新的触发时机由宿主设置决定。

## 记事簿工作台（v0.2.10）

「任务记录」和「旧快照」的列表卡片采用更小的字号和间距，长标题可换行。

打开已完成任务，在「本次归档结果」的保留 key 右侧点圆圈勾，即可更正为已归档。若该任务的清单仍用于下次归档，工作台会同步移除该 key。

输入区的模式、API、预设入口统一为纯图标按钮，归档模式使用叠层图标，自由模式使用对话图标。

修复审核点「全部保存」后误报「审核窗口已过期」。归档报告按已保存批次的写入回执核对 key 去向。更新并重载后，继续原任务即可自动校正前面批次的报告。

新建世界书条目默认开启「不可递归」和「防止进一步递归」，其他未指定属性沿用 TT 的新建模板。审核框跟随记事簿主题，工作台输入框随文字增高。启动或打开设置时会读取记事簿仓库的版本号，点当前版本号可重新检查。

归档审核在指定深度注入时可选消息角色，其他位置显示「不适用」。v0.2.5 修复旧批次保存时误报「消息角色超出允许范围」的问题，更新后可继续保存原审核草稿。

v0.2.4 修复归档审核点「全部保存」时可能出现的 `delayUntilRecursion 必须是有限数字` 报错。更新并重载前端后，可以在原聊天打开原批次继续保存，条目的递归开关和层数会保留。

气泡向下滑动打开独立工作台，提供归档/自由两种模式、独立 API 配置、所选设定与历史上下文、逐项审核、分批写入和30天修改快照。正文生成可以继续，工作台只提交可审核的修改草案。

输入区可切换模式、API 和预设。归档首轮直接回复规划，讨论确认后登记批次表格。执行每批前可以补充要求，带备注的批次可点开查看；助手消息不再使用限高代码框。API 设置每次编辑一个通道，支持弹窗添加、获取／刷新模型、测试、保存和删除。材料先按世界书启用，再选择条目；未启用的书不进入请求材料或工具权限。模型实际返回的推理可以展开查看，请求阶段和具体错误也会直接显示。

工具失败会停止本次批次，保留已生成内容、待审核草案和可导出的错误记录，等待用户手动重新提交或补充要求。TT 工具错误文件会自动读取，工具执行失败与模型请求失败分别显示。操作项数、正式编号重复、800 字与“了”字规则不再作为程序校验；归档文风仍可通过职责提示调整。

详见[工作台使用说明与边界](docs/workbench.md)。本版使用 TT 2.4 的独立提示词组装与后台 Agent 接口。

[实施与验证记录](docs/workbench-verification.md)：本机合成测试通过，真实 TT、服务商与手机体验仍待现场验收。

[v0.2.1 修正记录](docs/workbench-v0.2.1-review.md)说明双区域的原因、Claude 代理请求头修复、材料隔离及本轮验证范围。

## 使用

- 点贴边书签，收藏聊天可视区中央的楼层。点正文右上的书签可以精确选择。弹窗内一次选好备注、多个人物、多个合集和关键词。默认展示一、二级合集，点「显示三级」可展开三级合集。再次收藏同一楼进入编辑。
- 从书签往屏幕内侧滑动，打开主面板。主面板向停靠侧滑动即可收回。长按拖动书签后松开，可上下移动或吸附到另一侧。在「扩展 → Mnemosyne记事簿」展开折叠项，可关闭或恢复悬浮书签。折叠项与记事簿设置标题右侧均显示当前版本，发现新版时可点更新，再点「重载生效」。
- 「收藏」支持人物与合集两个方向的分组，以及人物、合集、关键词组合筛选。「消息」可按合集或人物浏览，再按剧情日期回看。
- 「收藏 / 消息 → 目录管理」可搜索完整路径，展开目录，点名称编辑，点「＋」创建子目录。人物、合集均支持三级；在编辑页选择上级目录即可移动，进入目录后也可从右上角编辑。各级都可设置元素、名称属性、多个完整名称和可选正则。完整名称和正则任一匹配即可。正则只用于归类。子合集在自己填写的人物标签上叠加各级上级合集的人物标签。一个块可以同时属于多个合集。规则中的人物标签可用半角或全角逗号、分号以及「、」分隔，如「玦；崔冬」。同名人物填完整路径。
- 在合集编辑页底部点「删除合集」并确认。子目录上移一级，遇到同名会添加序号。楼层收藏及备注保留；同一消息在其他合集的归属保留，仅命中已删合集的消息转入「未分类」。
- 默认发现 `div[data-nvwa-ui]`。陌生名称的通知可直接选择合集并记住别名，也可到「消息 → 按合集 → 未分类」多选消息，一次归入同一合集并记住选中消息的 UI 名称。详情中的「过滤此名称（黑名单）」需二次确认；同名旧消息随即隐藏，新消息也会跳过。可从过滤设置移除此名称并恢复识别。
- 「设置 → 过滤标签与剧情日期」可按属性名或 UI 名称忽略整个块，可设置剧情时间的标签或捕获正则。「零命中」默认关闭，开启后只在有实际 div 且缺少可识别标记时提醒。历史回填静默处理。
- 在「设置 → 导航栏位置」可将收藏、消息、设置切换到底部。选择窗口使用记事簿的主题色。
- 在设置中切换白绿、深蓝和墨绿霓虹主题，外部气泡可单独切换液态玻璃、磨砂光感玻璃，选择预设或自定义色值，换用书签、表情或本地图片图标。设置中的两个像素滑条可分别调节悬浮头和通知单行高度，拖动时实时预览。「气泡透明度」可在 0%–90% 之间调节，值越大，收藏头和通知下方的正文越清晰。通知默认从收藏头内侧上方弹出，也可移到应用顶部。

### 隐藏聊天楼层

记事簿底部显示当前聊天已隐藏的楼数，点旁边的「设置」可按范围隐藏或取消隐藏，起止楼都包含在内。也可以只保留最近若干楼（默认 20），一次将更早楼层隐藏、最近楼层恢复可见。勾选「保留第 0 楼」后，范围隐藏会跳过开场白，保留最近楼层时也会将开场白设为可见。操作沿用酒馆的消息隐藏标记并保存到当前聊天，影响发送给模型的上下文。

### 阅读显示方式

在「收藏正文」或单条消息详情里，可切换「前端 / 纯文本」，下次打开沿用上次的选择。默认用纯文本。「前端」按需调用酒馆显示正文时使用的格式化函数，保留正则生成的 HTML、内联样式、样式块和可展开的详情；未提供格式化接口时，优先使用宿主的正则处理接口，再回退到原文 HTML。拆分后的私信会带上原收件箱和标签容器的配色、CSS 变量及共享样式，只显示所选页的内容。已有索引在打开详情时即可使用这项修正。楼层正文两侧各留 12 像素，默认阅读字号为 14 像素。前端模式按比例缩放，保留时间戳、消息气泡与标题之间的大小关系。

阅读预览在独立窗口中排版，支持原生折叠、内嵌图片和女娲标签页的本地切换。依赖聊天区脚本、远程素材或宿主第三方样式表的界面可能与聊天区不同。预览不会执行正文脚本或发送草稿。打开列表或建立索引不会触发前端排版。

在「设置 → 阅读外观」可以预览字体，将字号调到 10–28 像素。默认使用霞鹜文楷 Regular。选择「跟随酒馆主题」时读取聊天正文的字体、字重、字形、文字颜色及底色。前端预览会复用可读取的主题字库声明，消息自身指定的样式仍优先。跨域样式表或宿主专用渲染器中的字体可能无法复用，此时也可在字体列表末尾选择「添加自定义字体」，导入同款字体。

自定义字体支持本地 TTF、OTF、WOFF、WOFF2 或允许跨域下载的字体文件直链。导入后存于当前设备，可跨聊天离线使用。自定义字体可在阅读外观中移除，聊天备份仅包含该聊天的收藏与规则。

## 本地数据与性能

收藏、手写备注、关键词、规则和来源索引写入当前 WebView 的专用 IndexedDB。消息原文、HTML、图片与草稿按钮均不写入索引。打开详情时从聊天读取，并校验来源。移除原文后，收藏备注仍保留。数据目录迁移或清理 WebView 前，可在设置里导出各聊天的收藏与规则，回到相同聊天后导入；自动索引由原文重建。

首次打开记事簿按每批最多 16 楼整理旧聊天，中途退出后可续扫。新回复、编辑和 swipe 只处理对应楼层；流式文字不触发连续识别。识别和自定义正则在专用 Worker 中运行。后续打开只加载目录页与必要的来源校验。同一标记新增别名时只重新处理已有候选楼层。新增外层属性、修改过滤或日期规则时会重新分批扫描。停用插件期间修改过旧楼层，可用「重新扫描当前聊天」校准索引。

## 开发验证

扩展直接使用 ES 模块，安装时无需构建或安装依赖。开发测试使用 Node.js 22 或更高版本，在此目录执行 `npm install` 和 `npm test`。测试数据均为合成样例。

### 一个收件箱里有多个人的私信

在「设置 → 拆分多标签消息」填入外层的完整 UI 名称，例如 `界内·新消息`。当这个 div 的直接子元素是 `div[data-nvwa-tabs]` 时，每个有名称的直接子页 `div[data-tab]` 各产生一条消息索引。回看时只读取该页在楼层原文中的范围。没有带名称的子页时继续显示原来的整块。

例如 `槐下听雨 · 12` 和 `无字碑 · 6` 分别显示为「界内·新消息 / 槐下听雨」和「界内·新消息 / 无字碑」。第一次从「未分类 → 选择合集并记住此名称」分别选已有的私信合集。下次计数变化时仍然沿用对应合集。也可以把完整显示名加到合集的 UI 名称列表。过滤完整子页名称只跳过该页，过滤外层名称会跳过整个收件箱。
