# 记事簿工作台

## 入口与最短流程

从记事簿贴边气泡向下滑动打开独立工作台；向内滑仍打开原记事簿，长按仍拖动气泡。记事簿标题栏也有“工作台”入口，键盘聚焦气泡后按向下箭头可打开。

1. 在“设置 → API 配置”选择当前 API，或点“添加 API”打开配置弹窗。填写地址与密钥后可获取／刷新模型，也可直接填写模型标识；“测试连接”发送固定短句验证正文返回，“保存 API”才保存当前编辑，“删除 API”移除当前通道。正文 API 借用 TT 当前连接、代理和模型；温度、最大输出、上下文窗口、流式、推理强度与超时使用记事簿自己的配置。输入区发送按钮左侧的两个小菜单可向上展开，切换 API 或提示词预设。
2. 在“材料”先启用世界书，再选择该书条目。每本世界书单独折叠，User／Char 单独分组。首次默认只选择 User／Char；已有明确保存的条目选择保留，并推导其所属世界书。禁用一本书会取消该书条目，内容、名称和创建权限均不作为本次世界书材料发送。“全选已启用”不会启用未选世界书。
3. 点输入区左上角“归档模式／自由模式”切换。归档模式先用普通对话规划、商量分组。回复“可以，开始吧”采用商定的方案，登记后可补充要求或开始第一批；自由模式直接查询或编辑设定。切换模式时，未完成任务保存在“任务记录”，无需先删除或放弃。生成或保存期间暂停切换。
4. 每批生成后点“审核本批修改”。旧文删除显示红色，最终文新增显示绿色；最终文字区域可直接点击编辑，世界书关键词、灯号、位置、深度、顺序等也可调整。点“继续下一个”仅保存审核草案，最后“全部保存”才写入本批通过的修改。某项可以跳过。
5. 保存一批后继续下一批。全部批次处理完才更新归档楼层；前面的批次已经独立落盘，不需要等五批全部生成再审核。

关闭工作台不会停止正在进行的后台请求；“停止”只取消记事簿的请求。工作台不会向正文提交助手消息。切换聊天会收起界面，写入前仍会核对固定聊天与目标身份。

## 助手、计划与请求进度

整个任务使用一个纵向聊天阅读区。分批计划来自模型的 `plan_archive` 工具调用，显示为“批次／主题／目标／条数”表格；点主题展开本批要求，规划说明另行折叠。它是待执行的任务数据，不是模型推理。旧版将它放在顶部长卡片，另用代码框显示工具之后的自然语言回复，造成看似两次输出和嵌套滚动。新版把计划作为聊天中的一张卡片，并明确要求模型不再重复整张计划表。

首轮助手直接用 Markdown 回复，包括范围内的 rolling key 去向、值得讨论的矛盾和分批建议。普通目标列编号或名称，特殊处理可单独说明。讨论达成一致后调用工具登记主题和目标，备注选填。每批开始前可在输入框提出针对本批或后续批次的调整，模型按最新要求生成草案。消息没有限高纵向滚动框；表格和代码仅在确有横向溢出时横向滚动。

发送后直接显示已知请求阶段。接口返回推理文本时出现可展开的“模型推理”，停止／失败后的已返回片段也会保留。模型不提供推理时不虚构推理块。流式期间轻量更新正文和已展开推理文本，完成后渲染 Markdown。自由模式只查询时可继续多轮讨论。

## 两种模式

### 归档模式

内置 S/P/R 与 rolling 整理职责：先检查归属、矛盾、过期信息、重复条目和已揭露条目；按计划分批提交完整正式条目。v0.2.3 取消操作项数上限，以及正式编号重复、单段超过 800 字和含“了”字的硬校验，草案提交和人工审核保存都不会因这四项被拦截。字数、用词和编号要求仍可通过职责与常用任务提示调整，由用户审核内容。目标权限、精确补丁匹配、来源版本和实际写入冲突仍会检查。

工具执行失败时，当前请求立即停止，不让模型自动修正重交，也不因后续 `workspace.finish` 将本批判成成功。完整草案、已收到的正文／推理和错误记录都会保留；草案尚未写入世界书。错误卡区分“工具执行失败”和“模型请求失败”，默认展开原因，可导出带版本号的 JSON 错误记录。TT 若只给出 `tool-results/...json` 路径，工作台自动读取该次调用的错误正文；旧任务的“查看上次 TT 运行记录”也会读取。文件不可读时保留原始报错、路径与读取失败原因，密钥与请求凭据会隐藏。

检查后可点击“手动重新提交”，输入框里的补充要求一并发送；也可先在对话里讨论，之后再点按钮。本次失败记录不会因重试消失。已有待审核草案可以先查看，也会随手动重试保留，提示模型只补交尚未提交的目标；出现部分实际写入时仍须从原审核流程恢复。TT 取消请求若未获确认会单独显示，不能将本地停止当作 TT 已确认结束。

工作台默认从最后归档楼层开始读取，包含该楼作为衔接边界，至最新楼或手工指定截止楼。读取的是原始消息，保留 endTime 后的 rolling，也包含正文界面已经隐藏的楼层。任务开始后范围固定：例如处理到250楼期间正文继续到280楼，任务结束仍只记录归档到250楼；成功完成后清除本次手动截止楼，下一任务默认读到当时最新楼。

输入框下方显示“已归档 100 / 250 楼”。带下划线的数字可点击手动调整。相对归档楼层，每增加50楼提醒一次；跳过多个阈值只弹一次追赶提醒，不会逐楼反复弹出。

**聊天中途首次使用**时，点击“已归档”数字，填上最后一次手动归档的楼号，勾选“从手动归档处接续”。在“材料”中选中已有归档的世界书条目或 User、Char 设定。工作台以这些材料衔接前情，正文从填写的楼层起读（含该楼），跳过更早的记忆总结。已因缺少总结而中断、尚未生成计划的任务，可直接点“重试当前阶段”。此选择按聊天保存，后续归档自动沿用；取消勾选后，新任务恢复使用记忆总结。

“清除 rolling key”只是归档记账，绝不删除或改写正文中的 rolling 标签。进行中的 key 保留原因与已并入条目，带入下次任务。closed 正式条目提交删除草案，经审核删除；同一世界书目标包含多个正式条目时，只移除对应段落，保留其余内容，旧全文保存在快照。只在全部批次保存后统一显示：

- 本次清除的滚动条目 key；
- 保留，下次再整理（含归档去向）；
- 本轮关闭条目。

跳过的归档去向不能使对应 key 被误报为已归档。保存结果不明确或出现冲突时，本批保持待处理，归档楼层不推进。期间手动改过归档楼层，后台任务不会覆盖手工值。

### 自由模式

按自由输入查询和编辑所选世界书、User 描述以及 Char 描述、性格、场景、开场白、对话示例、主提示词、历史后提示词。可一次调用工具对多个目标或多个不相连片段修改；局部替换必须精确匹配唯一旧文，不猜测重复片段。

只查询不产生快照；只有用户审核后的写入产生修改快照。世界书文件本身需已存在并与当前聊天/角色/全局/Persona 关联，工作台可在其中创建条目。

## API、提示词与记忆摘要

独立 API 在记事簿中添加，不读取记忆插件的 API 通道列表。密钥只存在本机插件设置与运行中的请求对象，不进入持久任务记录、修改快照或导出文档。

“助手默认预设”读取记忆插件已经配置的基础破限提示词，缺失时使用内置基础提示。它不借用记忆插件的总结任务说明。下拉菜单也提供 TT 已保存的聊天补全预设，使用 TT 的独立 PromptManager，保留预设的顺序、角色、深度、标记与宏处理，不切换正文正在使用的预设。

选材、楼层与助手职责本身是工作台的有意变化。它不保证重现所有第三方扩展在正文生成事件中临时增加的注入。要求的楼层、历史总结或所选材料被预设关闭、预算截断时应提示调整，而不能把未收到的正文标成归档完成。

主 API 保留 TT 按服务商存储的额外请求头（`additional_parameters_by_source[*].include_headers`）、代理 URL／密码、来源、模型与密钥引用。旧版误清空整个按来源参数容器，可能使依赖附加鉴权头或路由头的 Claude 反向代理失败；v0.2.1 已修正。主 API 仍不导入任意额外请求 body（`include_body`／`exclude_body`），防止正文配置覆盖本次材料、工具及工作台参数。没有实际代理错误明细时，不能把请求头丢失认定为所有调用失败的唯一原因。

材料权限在选材、捕获请求、读取工具、编辑／创建和写入时保持一致。未启用世界书不会通过预设的世界书激活快照重新加入。但用户另行选择的原文、历史总结或旧任务对话，可能本来就提到其中的名字或事实；这不代表插件额外发送了那本世界书。

默认归档方式通过记忆接口读取起始楼层之前的历史总结，放在本次正文上方。跨越边界且没有可拆分下级的摘要不能假装完整覆盖，缺口会显示并阻止归档。没有可用记忆插件时可以使用正文原文，工作台会声明没有历史摘要。如果 TT 只加载了末尾消息窗口（windowStartIndex 大于0），记忆插件当前公开接口仍使用本地索引，工作台暂不能证明绝对楼层衔接，会提示加载完整历史或改为从0楼提供原文。普通的正文隐藏标记不影响读取。L0 专项提取、时间线重组与其他记忆数据库数据调用暂不在本版实现。

## 自定义清洗标签

在「工作台设置 → 自定义清洗标签」输入标签后，点击「添加标签」或按 Enter。可逐项添加、删除多条规则，最后「保存设置」。未点添加的最后一条有效输入也会随保存加入。默认列表为空，保持旧版发送正文的行为。规则保存在工作台全局设置，归档／自由模式、正文主 API／独立 API 共用，下一次请求捕获正文时生效。

| 规则 | 清洗范围 |
| --- | --- |
| `sxrp` 或 `<sxrp>` | 所有 sxrp 块，包括带 guests 等属性的块 |
| `<archive>` | 所有 archive 块，不区分属性 |
| `<archive type="关系">` | 仅含 `type="关系"` 的 archive 块，允许其它属性 |

名称忽略大小写，属性值精确匹配；属性顺序、单双引号及空白不影响匹配。多个条件在同一条规则内必须全部满足，多条规则之间任一符合即清洗。标签名精确匹配，不把 archive-extra 当成 archive，不支持正则表达式。匹配块的开标签、闭标签、嵌套内容一起移除；自闭合标签移除自身。匹配到完整开标签后若未闭合，清洗到该条消息末尾，不跨楼层处理。

清洗只针对所选聊天楼层中的正文投影。原聊天、楼层号、角色、来源版本签名完整保留；即使只修改被清洗掉的原文，旧任务的写入检查仍会识别变化。整楼清洗为空时保留空楼标记，不回退原文。正文宏和上下文完整性校验也使用清洗后的内容。「楼层与历史 → 查看实际请求材料」显示同一份结果。

所选世界书、User／Char 设定、历史总结及工作台自身对话不应用这些规则。它们可能另行包含相同内容，已发送给模型的历史回复也不会追溯删除。可用「导出标签」备份规则，用「导入标签」合并后再保存；JSON 使用 `kind: mnemosyne-clean-tags`、`version: 1`，只含清洗规则。工作台设置 schema 升为 4，旧设置自动补空列表，无需迁移聊天或档案。

规则只在一次捕获时编译并清洗已有读取结果；页面刷新、流式输出和同次请求的工具轮次不重复读取或清洗正文。扫描使用有界分片，长正文处理中让出事件循环。

## 快照、恢复和中断

审核写入前先持久化旧文、新文和保存意图；每本世界书合并写一次，再校验实际结果。没有跨世界书/角色卡/Persona 的全局原子事务，部分失败会逐项显示。已确认成功的项不会在重试时重复写入。结果不确定时重试同一保存意图，不生成另一个操作盲写。

旧快照可查看完整新旧版本、条目属性和原始导入字段，多选导出单个 Markdown。回退较早快照会读取当前内容，生成“当前版本 → 选中旧版本”的新审核草案；通过同一审核流程保存，并保留回退自身的快照。

默认保留30天，可在设置修改。打开工作台时按索引有界清理到期快照，每批最多100项，后续批次让出事件循环。尚未确认结果的保存意图不自动清除。完成任务的条目版本副本会移除，完整旧文由快照保管；任务对话与未完成审核草案保留。

网络中断、超时或停止时保存已完整提交的工具草案与不完整的可见回复；不会把截断 JSON 猜成修改。刷新后从任务记录恢复；继续生成时重新读取连接和材料，并校验原文版本。正文被编辑、删除或切换 swipe 后，旧草案不能继续直接写入。

“无进展超时”默认 600 秒。TT 报告新的运行步骤或收到模型正文、推理、工具调用时，工作台重新计算等待时间。无流式输出时按最后可见阶段计时。超时提示显示通道、等待时长和最后阶段。使用正文主 API 的出错任务可点“查看上次 TT 运行记录”，一次读取最近 40 条 TT 事件。失败行可展开查看 TT 返回的错误说明，第一处失败默认展开。首轮使用普通聊天补全，调用错误直接显示在工作台对话中。

重开审核会读取持久保存意图。跳过失败项时先核对宿主实际落盘结果：未写入则撤掉对应待保存缓存后跳过；已经写入则按实际成功显示，需要从快照另建回退；无法确定则保留待处理。停止生成后的旧工具回调不能把草案混入同一任务的后续重试。

## 性能与验证边界

- 工作台界面与 TT 适配器按需加载，正文事件不扫描世界书或全部历史。
- 归档提醒按事件去重；每个聊天只读一次提醒设置，修改后更新缓存。
- 流式正文／推理／阶段80毫秒合并更新，只更新当前节点；折叠推理不反复写入长文本，已完成 Markdown 消息复用节点。没有新增轮询或逐 token 数据库存储。
- 正文 diff 在独立 Worker 计算，采用有界锚点算法；Worker 不可用时对长文降为整段标红/标绿。
- 审核输入180毫秒合并计算差异，中文输入法组合期间暂停重算；草案900毫秒防抖持久化。
- 材料每页20本书、展开每本先显示40项，搜索最多自动展开前三本；勾选和折叠不重读宿主。任务与快照分页显示，只读小型索引记录，完整版本按需读取，避免列表反序列化大量正文。
- 批量 Markdown 导出在记录间让出事件循环，并限制单次体积。

适配目标为 TT 2.4 独立提示词组装和后台 Agent 接口，缺少相应能力时明确报错。Node/fake IndexedDB/无网络宿主模拟测试不等同于真实手机和实际模型调用。没有在测试中调用付费模型或使用真实 RP 数据。
