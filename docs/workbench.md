# 记事簿工作台

## 入口与最短流程

从记事簿贴边气泡向下滑动打开独立工作台；向内滑仍打开原记事簿，长按仍拖动气泡。记事簿标题栏也有“工作台”入口，键盘聚焦气泡后按向下箭头可打开。

1. 在“设置”填写独立 OpenAI 兼容 API，或选择“正文主 API”。主 API 只借用 TT 当前聊天补全连接与模型；温度、最大输出、上下文窗口、流式、推理强度与超时使用记事簿自己的配置。
2. 在“材料”选择 User、Char 及世界书条目。默认选中 User、Char 和未禁用的常驻蓝灯；绿灯手动选择。可全选、全不选或恢复默认。已选材料带类型标签、稳定目标 ID 与世界书元信息。
3. 归档模式先发送“整理条目”或自由要求，讨论分批计划，再点“按计划开始第一批”。自由模式直接输入查询或编辑要求。
4. 每批生成后点“审核本批修改”。旧文删除显示红色，最终文新增显示绿色；最终文字区域可直接点击编辑，世界书关键词、灯号、位置、深度、顺序等也可调整。点“继续下一个”仅保存审核草案，最后“全部保存”才写入本批通过的修改。某项可以跳过。
5. 保存一批后继续下一批。全部批次处理完才更新归档楼层；前面的批次已经独立落盘，不需要等五批全部生成再审核。

关闭工作台不会停止正在进行的后台请求；“停止”只取消记事簿的请求。工作台不会向正文提交助手消息。切换聊天会收起界面，写入前仍会核对固定聊天与目标身份。

## 两种模式

### 归档模式

内置 S/P/R 与 rolling 整理职责：先检查归属、矛盾、过期信息、重复条目和已揭露条目；按计划分批提交完整正式条目。正式世界书条目默认检查 800 字限制、禁用“了”字及重复编号。职责与常用任务提示可以在设置中修改；改用其他写法时可关闭文风检查。人工审核修订不受文风检查限制，编号重复与写入冲突仍会检查。

工作台默认从最后归档楼层开始读取，包含该楼作为衔接边界，至最新楼或手工指定截止楼。读取的是原始消息，保留 endTime 后的 rolling，也包含正文界面已经隐藏的楼层。任务开始后范围固定：例如处理到250楼期间正文继续到280楼，任务结束仍只记录归档到250楼；成功完成后清除本次手动截止楼，下一任务默认读到当时最新楼。

输入框下方显示“已归档 100 / 250 楼”。带下划线的数字可点击手动调整。相对归档楼层，每增加50楼提醒一次；跳过多个阈值只弹一次追赶提醒，不会逐楼反复弹出。

**聊天中途首次使用**时，点击“已归档”数字，填上最后一次手动归档的楼号，勾选“从手动归档处接续”。在“材料”中选中已有归档的世界书条目或 User、Char 设定。工作台以这些材料衔接前情，正文从填写的楼层起读（含该楼），跳过更早的记忆总结。已因缺少总结而中断、尚未生成计划的任务，可直接点“重试当前阶段”。此选择按聊天保存，后续归档自动沿用；取消勾选后，新任务恢复使用记忆总结。

“清除 rolling key”只是归档记账，绝不删除或改写正文中的 rolling 标签。进行中的 key 保留原因与已并入条目，带入下次任务。closed 正式条目提交删除草案，经审核删除；同一世界书目标包含多个正式条目时，只移除对应段落，保留其余内容，旧全文保存在快照。只在全部批次保存后统一显示：

- 本次清除的滚动条目 key；
- 保留，下次再整理（含归档去向）；
- 本轮关闭条目。

跳过的归档去向不能使对应 key 被误报为已归档。保存结果不明确或出现冲突时，本批保持待处理，归档楼层不推进。期间手动改过归档楼层，后台任务不会覆盖手工值。

### 自由模式

按自由输入查询和编辑所选世界书、User 描述以及 Char 描述、性格、场景、开场白、对话示例、主提示词、历史后提示词。可一次调用工具对多个目标或多个不相连片段修改；局部替换必须精确匹配唯一旧文，不猜测重复片段。

只查询不产生快照；只有用户审核后的写入产生修改快照。世界书文件本身需已存在并与当前聊天/角色/全局/Persona 关联，工作台可在其中创建条目。

## API、提示词与记忆摘要

独立 API 在记事簿中添加，不读取记忆插件的 API 通道列表。密钥只存在本机插件设置与运行中的请求对象，不进入持久任务记录、修改快照或导出文档。

“助手默认预设”读取记忆插件已经配置的基础破限提示词，缺失时使用内置基础提示。它不借用记忆插件的总结任务说明。下拉菜单也提供 TT 已保存的聊天补全预设，使用 TT 的独立 PromptManager，保留预设的顺序、角色、深度、标记与宏处理，不切换正文正在使用的预设。

选材、楼层与助手职责本身是工作台的有意变化。它不保证重现所有第三方扩展在正文生成事件中临时增加的注入。要求的楼层、历史总结或所选材料被预设关闭、预算截断时应提示调整，而不能把未收到的正文标成归档完成。

主 API 不导入 TT 的任意额外请求 body（custom_include_body、custom_exclude_body、additional_parameters），防止正文采样与工具覆盖重新进入工作台；依赖这些 body 扩展的代理需改用兼容通道或等待进一步适配。

默认归档方式通过记忆接口读取起始楼层之前的历史总结，放在本次正文上方。跨越边界且没有可拆分下级的摘要不能假装完整覆盖，缺口会显示并阻止归档。没有可用记忆插件时可以使用正文原文，工作台会声明没有历史摘要。如果 TT 只加载了末尾消息窗口（windowStartIndex 大于0），记忆插件当前公开接口仍使用本地索引，工作台暂不能证明绝对楼层衔接，会提示加载完整历史或改为从0楼提供原文。普通的正文隐藏标记不影响读取。L0 专项提取、时间线重组与其他记忆数据库数据调用暂不在本版实现。

## 快照、恢复和中断

审核写入前先持久化旧文、新文和保存意图；每本世界书合并写一次，再校验实际结果。没有跨世界书/角色卡/Persona 的全局原子事务，部分失败会逐项显示。已确认成功的项不会在重试时重复写入。结果不确定时重试同一保存意图，不生成另一个操作盲写。

旧快照可查看完整新旧版本、条目属性和原始导入字段，多选导出单个 Markdown。回退较早快照会读取当前内容，生成“当前版本 → 选中旧版本”的新审核草案；通过同一审核流程保存，并保留回退自身的快照。

默认保留30天，可在设置修改。打开工作台时按索引有界清理到期快照，每批最多100项，后续批次让出事件循环。尚未确认结果的保存意图不自动清除。完成任务的条目版本副本会移除，完整旧文由快照保管；任务对话与未完成审核草案保留。

网络中断、超时或停止时保存已完整提交的工具草案与不完整的可见回复；不会把截断 JSON 猜成修改。刷新后从任务记录恢复；继续生成时重新读取连接和材料，并校验原文版本。正文被编辑、删除或切换 swipe 后，旧草案不能继续直接写入。

“无进展超时”默认 600 秒。TT 报告新的运行步骤或收到模型正文、推理、工具调用时，工作台重新计算等待时间。无流式输出时按最后可见阶段计时。超时提示显示通道、等待时长和最后阶段。使用正文主 API 的出错任务可点“查看上次 TT 运行记录”，读取该任务最近一次 TT 运行的阶段与已有错误码。

重开审核会读取持久保存意图。跳过失败项时先核对宿主实际落盘结果：未写入则撤掉对应待保存缓存后跳过；已经写入则按实际成功显示，需要从快照另建回退；无法确定则保留待处理。停止生成后的旧工具回调不能把草案混入同一任务的后续重试。

## 性能与验证边界

- 工作台界面与 TT 适配器按需加载，正文事件不扫描世界书或全部历史。
- 归档提醒按事件去重；每个聊天只读一次提醒设置，修改后更新缓存。
- 流式文本80毫秒合并更新，只更新当前文本节点。
- 正文 diff 在独立 Worker 计算，采用有界锚点算法；Worker 不可用时对长文降为整段标红/标绿。
- 审核输入180毫秒合并计算差异，中文输入法组合期间暂停重算；草案900毫秒防抖持久化。
- 材料、任务与快照分页显示。任务/快照列表只读小型索引记录，完整版本按需读取，避免列表反序列化大量正文。
- 批量 Markdown 导出在记录间让出事件循环，并限制单次体积。

适配目标为 TT 2.4 独立提示词组装和后台 Agent 接口，缺少相应能力时明确报错。Node/fake IndexedDB/无网络宿主模拟测试不等同于真实手机和实际模型调用。没有在测试中调用付费模型或使用真实 RP 数据。
