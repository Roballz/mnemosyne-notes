## 原因与改动

### 1. 双区域与排版

旧上方卡片读取 `plan_archive` 的 explanation、batches[].title／instructions；下方区域读取工具之后的最终助手回复。独立通道会把工具结果交回模型继续回复，故往往先出现计划，再出现另一份自然语言摘要。旧版既未限制计划详情的写法，也未渲染 Markdown，并把完整消息放入限高的 pre 元素，产生代码框背景、原始标记和双重纵向滚动。

现在整个任务使用一个聊天阅读区：计划作为消息中的表格，说明和每批详情按需展开；状态与操作收为底部小工具栏。提示词及工具参数说明要求简短主题、“目标 → 改动”项目符号和目标列表，工具返回后不再重复整个计划。旧计划原文保留，只改变展示方式。

消息使用独立 Marked 17.0.5 解析器，原始 HTML 按字面显示；输出通过元素白名单重建，禁止脚本、样式、事件属性、嵌入和远程图片。与正文的正则／宏流程分离，避免再次处理用户正文。MIT 许可及来源保存在 `lib/workbench/vendor`。

### 2. 模式、API 与预设

自由模式原本存在，但原生 select 外观像标签，未完成任务时还会禁用。现在模式按钮带明确展开符号；空闲时可以直接切换，原任务保留在任务记录，生成／保存期间禁止切换。自由模式的纯查询保留为讨论，可继续追问。

API／预设移到发送按钮左侧，向上展开；菜单统一锚定到工具栏，避免短 API 名称使预设菜单越过左边界。设置只显示当前 API 的一个编辑器，添加使用独立弹窗，保留外层尚未保存的生成参数。支持获取／刷新模型、保存、删除及实际短句测试。

测试仅发送固定验证短句，不带材料或工具；收到正文才算成功，不把测试成功当作全部工具调用兼容性验证。更改 URL／密钥、切换通道、关闭窗口会取消检测，并忽略迟到结果。删除／保存通道与外层设置草稿保持一致，避免外层保存复活已删除通道。

### 3. 正文 Claude／反向代理

已确认的缺陷：原 `captureConnection` 与 `applyGenerationSettings` 把 `additional_parameters_by_source` 整个置空。TT 当前实现从该容器按来源读取 include_headers，旧顶层 custom_include_headers 不是该路径的实际取值点。依赖额外鉴权或路由头的代理可能因此失败。

修正保留每来源请求头到实际设置和冻结连接，继续保留代理 URL／密码、来源、模型和密钥引用；工作台仍独立控制生成参数，正文的任意 body 覆盖项仍不导入。Claude thinking／预算／采样转换继续交给 TT 原有 builder。

源码证据：

- [TT openai.js](https://github.com/Darkatse/TauriTavern/blob/fff9af0333be97697be2313981699ab0ce35c236/src/scripts/openai.js)：`getAdditionalParametersForSource`、`applyAdditionalParametersToRequest`、请求构造与代理参数。
- [冻结连接服务](https://github.com/Darkatse/TauriTavern/blob/fff9af0333be97697be2313981699ab0ce35c236/src-tauri/crates/tt-application/src/services/prompt_assembly_service.rs)：连接字段保存和重新组装。
- [Claude builder](https://github.com/Darkatse/TauriTavern/blob/fff9af0333be97697be2313981699ab0ce35c236/src-tauri/crates/tt-application/src/services/chat_completion_service/payload/claude/builder.rs)：模型原生参数转换。

用户本次只提供“模型调用失败”的概述，没有上游错误文本，无法证明请求头缺失就是其唯一原因。现已直接显示脱敏的具体错误、HTTP／阶段信息，并保留按需读取 TT 运行记录的入口。

### 4. 推理和材料范围

独立通道读取 reasoning_content／reasoning／reasoning_details；正文通道读取 TT 的实际推理投影。仅在确有推理文本时显示推理块。无推理时仍显示请求阶段。成功和中断片段可保存，推理展示内容不作为下一轮普通对话重新发送；同次工具往返需要的协议字段由 transport 保留。

旧选材的确定问题是把所有挂载世界书名称都列为可创建目标，并按该范围授权创建；已有条目也可能在最终拒绝前被读取。未发现 TT 按预设自动重新注入全部未选世界书正文的证据。

现在每本书单独分组、显式启用，再选择条目。书级权限和条目 ID 在任务、请求捕获、工具读取／修改和最终写入保持一致；未选已有条目在宿主读取前拒绝。首次只默认选 User／Char；已有明确保存的条目选择推导所属书，显式空书列表保持空。原文、历史总结或旧对话里已经包含的相关名字／事实不会被改写或删除。

## 性能与集成检查

- 没有新增后台轮询、逐 token 持久化或正文事件全库扫描。
- 流式正文／推理／状态80ms合并更新，原生投影60ms合并；只更新活动节点。折叠推理不反复写入长文本，流式显示最多保留最新24,000字符，最终完整内容保留。
- 完成消息的 Markdown 节点复用，缓存只覆盖可见24条消息；离开窗口的节点主动移除缓存。详情展开才解析，避免每个状态更新重排全部历史。
- 材料每页20本书、每本展开先40项；搜索最多自动展开前三本，折叠／选择不重读宿主。
- 模型列表最多创建200个选项，完整列表保存在当前编辑器内；150ms防抖筛选，每扫描2,000个名称让出事件循环，不重复联网。
- 写入成功后增量更新新条目正式 UID 缓存，防止选材归一化误删新条目；后续批次正常读取。结束发送后立即解锁任务按钮，关闭设置后补显示后台完成的回复。
