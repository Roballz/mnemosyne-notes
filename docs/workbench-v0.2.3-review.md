## 实现

1. 移除工具 schema、控制器的 60 项上限及准备／保存链路的 100 项上限。保留非空操作数组、内部审核 ID 唯一、目标权限和实际写入冲突校验。
2. 移除正式编号重复、800 字、含“了”字的提交与审核保存拦截，删除文风校验开关。已有自定义提示词原样保留；内置文风提示仍可编辑。
3. 根据失败事件及对应 `tool_result_stored` 记录定位本次调用的结果文件，读取真实错误正文。旧任务运行日志同样支持。文件读取最多等待 5 秒，读取失败保留原事件、路径及读取异常；不读取参数文件，诊断隐藏密钥和请求凭据。
4. 工具错误与模型请求错误使用独立类别。错误记录带 `version: 1`，写入任务对话，可展开和导出 JSON；后续重试不会删除旧记录。
5. 独立 API 工具失败后退出当前工具循环，不执行剩余调用，不向模型回送错误开启自动修正轮。TT 插件回调失败立即锁定本次失败并请求取消；原生日志中的工具失败同样先取消再读错误文件。随后到达的完成事件不能覆盖失败状态。
6. 显示“手动重新提交”，本次输入与错误原因随用户手动请求发送。已有草案、已收到正文和推理保留，可先讨论或审核。部分实际写入仍须通过原审核日志恢复，不得换任务重放。
